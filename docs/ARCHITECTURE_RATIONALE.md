## 2. สรุปประเด็นสำคัญของแต่ละงาน (สำหรับผู้อ่าน)

### 📕 U-Net (ปี 2015) — ทำไมถึงเหมาะกับงานนี้
- **ปัญหาเดิม:** segmentation ภาพชีวการแพทย์มักสับสน "position" กับ "context" (ต้องรู้ทั้งตำแหน่งและบริบทโดยรอบ)
- **วิธีแก้:** ใช้ **skip connection** ดึงเอาสารสนเทศระดับ detail (ขอบ/ลายละเอียด) จากฝั่ง encoder มาเติมเข้า decoder ตรงตำแหน่งเดียวกัน ทำให้ได้เอาต์พุตที่**คมชัดและรู้ตำแหน่งถูกต้อง**
- **เหตุผลที่ตรงกับงาน:** ต้นในขวดมี**ขอบเขตชัดเจนแต่มีรายละเอียดเยอะ** (ใบ, เส้นใบ, ลำต้น) → U-Net เก็บทั้ง "ภาพรวม" และ "รายละเอียด" พร้อมกัน

### 📗 MobileNetV3 (ปี 2019) — ทำไมต้อง encoder เบาๆ
- **ปัญหา:** SAM3 หนักมาก (848M params) ต้อง GPU → deploy ยาก ต้นทุนสูง
- **วิธีแก้:** MobileNetV3-Small ผ่าน NAS ออกแบบมาให้**เบา เร็ว พารามิเตอร์น้อย** (~3.6M รวมทั้งโมเดล)
- **เหตุผลที่ตรงกับงาน:** เป้าหมายคือ**ระบบต้นทุนต่ำ ใช้งานบนอุปกรณ์ทั่วไป** (สมาร์ตโฟน/คอมธรรมดา) ไม่ใช่ศูนย์คอมพิวเตอร์ → ต้องเลือก backbone เบา

### 📘 เหตุผลรวม (synthesis) — กลั่นจาก SAM3 สู่ U-Net
- **SAM3** ทำหน้าที่ **teacher** → สร้าง pseudo-labels (ผลที่แม่นสุด ตาม Orvati Nia 2026)
- **U-Net** >> ถูกฝึกจาก labels เหล่านั้น + seeds → หลังกลั่น (distill) ได้ความแม่นใกล้เคียง (val_dice ≈ 0.98) แต่**เล็กกว่า 240 เท่า** → ใช้งานจริงได้

## 3. 🧠 สรุปเป็น "why" กระชับๆ 3 บรรทัด (ใช้พูด/เขียนได้เลย)
> 1. **U-Net** เพราะ skip connection เก็บรายละเอียดของต้น (ใบ/เส้นใบ) ได้แม่น — val_dice 0.98
> 2. **MobileNetV3-Small** เพราะเบา-เร็ว (~3.6M params) — deploy บนอุปกรณ์ทั่วไปได้ ตรงเป้า low-cost
> 3. **กลั่นจาก SAM3** เพราะได้ความแม่นใกล้ teacher แต่ต้นทุนการคำนวณต่ำกว่ามาก — trade-off ระหว่าง accuracy กับ cost

## 4. สิ่งที่ควรรู้/ระวังในการเขียน (counter-argument)
- Orvati Nia 2026 ชี้ว่า SAM3 แม่นสุด **แต่ช้า/แพง** → ต้องเกริ่นตรงๆ ว่าการกลั่นเป็น U-Net คือการ**ยอมรับความแม่นบางส่วนเพื่อแลกกับต้นทุน**
- โมเดลเทรนบน**ชุด greenhouse สาธารณะ** (ไม่ใช่ pseudo-label จาก 100 ขวด) → เป็น prototype, ให้ 100 ขวดเป็น test/eval only (ตาม `space/README.md`)
- **ยังต้องยืนยัน** ว่า 2D feature แยก verdict ได้ปานกลาง (acc ~0.65) → หนุนการพัฒนาต่อเป็น 3D
